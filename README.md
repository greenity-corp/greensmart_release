# 그린스마트 플랫폼 공개 안내

> 문서 기준일: 2026-10-20 · 용도: 고객·설치/유지보수 담당자에게 제공할 공개 제품 안내와 릴리즈 탐색

그린스마트는 **Core를 공통 기반으로 Cloud·Edge·Controller가 협력하는 플랫폼**입니다. Cloud는 메인서버, Edge는 농장의 로컬 엔드서버이자 판단의 중심, Controller는 IoT·PLC의 연결·관측·허용된 실행을 담당합니다. 이 저장소는 네 앱의 관계와 승인된 공개 배포 정보를 찾는 입구입니다. 제품 소스와 상세 설계의 원본은 접근을 제한한 `greenity-corp/green_smart` 저장소에서 관리합니다.

## 1. 공개 저장소 구조와 앱의 역할

| 구분 | 역할·주사용자 | 공개 안내·릴리즈 |
| --- | --- | --- |

| Core | 세 앱 구동의 기반, 공통 규격·라이브러리·계약 지원·UI 컴포넌트·템플릿. 각 앱의 업무 판단과 권한 원본은 해당 앱이 소유 | 독립 공개 저장소·설치 파일을 제공한다고 선언하지 않음. 공개 배포 시 각 앱의 실제 Core 소비 버전과 지원 조건으로 연결 |

이 저장소는 안내 허브입니다. Cloud·Edge·Controller의 설치 산출물은 각 전용 채널에서 구분하며, 전체 제품 ZIP이나 임의의 통합 설치 파일이 있다고 가정하지 않습니다. 논리 앱·기능 모듈이 각각 별도 서버나 별도 저장소를 뜻하지 않습니다.

## 2. 현재 확인한 게시 상태와 계획의 범위

2026-10-20 12:54 KST에 GitHub Releases API를 조회한 결과, 이 허브와 위 세 앱 저장소 모두 반환된 릴리즈 목록이 비어 있었습니다. 이 시각의 게시 현황이며 이후의 최신 정보는 각 릴리즈 목록에서 다시 확인하세요. 기존 현장의 설치·운영 유무를 조사한 결과나 특정 버전의 지원 선언은 아닙니다.

현재 공개한 이 안내만으로 검증된 설치 파일·지원 버전 조합·다운로드 경로·설치 명령을 제공하지 않습니다. 새 기준 문서의 정비와 앱 구현·검사·공개 출고는 별개의 단계입니다. 향후 순서는 **문서 기준 정리 → UI 템플릿/컴포넌트 레퍼런스 비교·선정 → 최소 구현·검사 → 승인된 배포**입니다.

확정된 제공 방향은 다음과 같습니다.

- Cloud·Edge·Controller는 기존 서버·장치 실행부를 유지하고 별도의 데스크톱·모바일 클라이언트에서 접속·관리합니다. 사용자 앱을 종료해도 서버·장치 실행부를 함께 종료하는 구조로 설계하지 않습니다.
- 공통 기반 언어의 클라이언트 원본을 OS별로 빌드하는 방향이며 **Windows·Linux를 우선**, Android·iOS·macOS는 후속 개발합니다. 지원 최소 OS·CPU·Linux 배포판과 실제 제공 파일은 각 릴리즈의 검증 결과로 확정합니다.
- 프레임워크·UI 라이브러리·패키징 방식은 선정과 실제 OS 검증이 필요합니다. 계획에 기술 이름이 있다고 채택·설치·지원이 완료된 것은 아닙니다.
- 작물 공통 기반을 먼저 계획합니다. 특정 작물의 재배·예측·방제 기능과 장치/PLC 모델은 개별 검증·지원 범위로 안내합니다.

## 3. 사용자가 공개 정보를 확인하는 순서

1. 사용할 앱의 안내에서 **클라이언트·서버 실행부·장치 실행부 중 무엇이 필요한지** 확인합니다. 같은 앱 이름이라도 산출물 종류와 설치 대상은 다를 수 있습니다.
2. 해당 릴리즈의 정식/사전 배포 여부, 공개 변경 내역, 알려진 제한과 지원 종료·철회 상태를 읽습니다. 저장소의 `main`이나 최신 날짜만으로 설치 대상을 정하지 않습니다.
3. 현재 현장의 Cloud·Edge·Controller와 각 클라이언트, Core 소비 자산·계약/데이터 형식을 지원 조합과 비교합니다. 동일 버전 문자열만으로 호환성을 판단하지 않습니다.
4. 대상 OS/CPU·장치/profile·서버 접속 조건, 사전 백업·복원 조건과 적용 순서를 확인합니다. 누락되거나 미검증인 조합은 담당자의 확인을 받습니다.
5. 승인된 릴리즈가 명시한 자산만 내려받고, **그 자산에 연결된** 체크섬·서명·신뢰 가능한 발행자/출처의 검증 절차를 따릅니다. 검사 방법·검증 키를 임의로 추측하지 않습니다.
6. 설치 뒤 버전·기동·현재 권한·연결·데이터·필요한 업무 결과를 각각 확인합니다. 다운로드·설치 프로세스 종료·화면 표시만으로 현장 기능 검증을 완료하지 않습니다.

GitHub가 릴리즈에 자동으로 제공하는 `Source code (zip/tar.gz)`는 해당 공개 저장소의 태그 시점 내용을 묶은 것입니다. 설치 프로그램이나 비공개 제품 소스 전체를 뜻하지 않습니다. 릴리즈의 태그와 배포 설명·자산 관계는 [GitHub 공식 릴리즈 문서](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases)를 참고하세요.

## 5. 업데이트 실패·단절·복구

- 적용 전에 대상·영향·담당자·중단/복원 조건을 확인합니다. 공개 안내 정비만으로 자동 업데이트나 운영 배포를 시작하지 않습니다.
- 응답이 없으면 기존 요청의 실제 결과와 현장 상태부터 확인합니다. 결과 불명을 성공/실패로 임의 확정하거나 새로운 제어 요청으로 바꾸어 반복하지 않습니다.
- Cloud 단절은 Edge 현장 판단을 Cloud/Controller로 넘기는 이유가 아닙니다. 실제로 유지 가능한 로컬 업무는 유효한 권한·관측·DB·현장 안전 조건에 따라 판단합니다.
- 복원은 프로그램 버전 되돌림과 동일하지 않습니다. DB/파일·미완료 작업·장치 상태·현재 유효한 권한/연결 관계까지 확인하며, 오래된 백업을 복원했다는 이유로 회수된 권한을 다시 허용하지 않습니다.
- 현장 장치가 연관된 조치는 해당 릴리즈와 현장 담당자가 확인한 절차를 따릅니다. 일괄 정지·장치 재연결·반복 쓰기를 일반 복구법으로 안내하지 않습니다.

## 6. 데이터·보안·지원

플랫폼 기본 방향은 **A 농장이 A 농장 정보와 서버가 공유를 허용한 공용 정보만 받는 것**입니다. 같은 기상 자료를 재사용한다고 다른 농장의 관측·일지·고객/장치 명단을 공유하지 않습니다. Core UI 코드를 함께 쓴다는 사실도 데이터 공유 권한을 만들지 않습니다. 이 기준의 문서화와 실제 격리 구현·시험 완료를 구분합니다.

공개 저장소에는 승인된 일반 제품 안내·릴리즈 설명·공개 허용 산출물만 올립니다. 비공개 기준 문서 원문, 내부 개발 PR/CI 로그, 고객/농장/장치 식별정보, 내부 주소·설정, 비밀번호·토큰·인증서 개인키·서명키, 검증하지 않은 바이너리와 임의의 체크섬은 올리지 않습니다.

문의할 때는 공개 가능한 앱/산출물 버전·OS·발생 시각·민감정보를 제거한 증상과 이미 수행한 확인을 정리합니다. 계약·설치 인계 등으로 지정된 비공개 지원 창구가 있으면 그 경로를 이용하고, 공개 이슈에 현장 원문 로그·설정·데이터를 붙이지 않습니다. 별도 공개 연락처·응답 시간·무상 지원 범위는 아직 이 문서에서 선언하지 않습니다.

## 7. 문서 유지관리

제품 기준은 비공개 원본에서 일관되게 관리하고, 공개 안내는 공개 검토를 거친 내용으로 갱신합니다. 앱 기능·지원 조합·자산·보안 안내가 달라지면 해당 릴리즈 설명과 이 허브/전용 앱 안내의 링크·상태를 함께 확인합니다. 변경 근거·검사 결과·운영 피드백은 다음 계획에 반영하며 내부 기록을 그대로 공개하지 않습니다.

문서 최신화는 기존 릴리즈의 재서명·자산 변경·출고 승인이 아닙니다. 실제 릴리즈 게시와 설치/운영 적용은 각각 필요한 검토와 승인을 거칩니다.
